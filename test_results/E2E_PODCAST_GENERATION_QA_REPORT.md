## 🐛 발견된 이슈

### Issue #1: 2-Stage 플로우 미구현 ⚠️ HIGH PRIORITY

**심각도**: High
**영향도**: 사용자 경험 - 대기 시간 3배 증가

**현황**:
- E2E-TEST-FINAL-VERIFICATION.md에 문서화된 2-stage 플로우가 실제로는 작동하지 않음
- Stage 1 (Intro) → 즉시 페이지 표시 → Stage 2 (Rest) 백그라운드 생성 플로우가 없음
- 대신 1-stage 전체 생성 방식으로 작동

**증거**:
1. 진행률: 0% → 98% → 100% (한 번에)
2. POST API 1회만 호출 (stage 파라미터 없음)
3. 페이지 표시: 100% 완료 후에만
4. 콘솔 로그: "NotebookLM 스타일 전체 팟캐스트 생성 시작" (1회만)

**예상 원인**:
```typescript
// 예상되는 코드 (현재 구현)
async function generatePodcast() {
  // 1-stage: 전체 생성
  const response = await fetch('/api/tts/notebooklm/generate', {
    method: 'POST',
    body: JSON.stringify({ location, language }) // stage 파라미터 없음
  });

  // 페이지 전환
  router.push(`/podcast/${language}/${location}`);
}

// 기대되는 코드 (2-stage)
async function generatePodcast() {
  // Stage 1: Intro만
  const stage1 = await fetch('/api/tts/notebooklm/generate', {
    method: 'POST',
    body: JSON.stringify({ location, language, stage: 'intro' })
  });

  // 즉시 페이지 전환
  router.push(`/podcast/${language}/${location}`);

  // Stage 2: Rest 백그라운드
  fetch('/api/tts/notebooklm/generate', {
    method: 'POST',
    body: JSON.stringify({ location, language, stage: 'rest', episodeId })
  }); // await 없음 (백그라운드)
}
```

**권장 조치**:
1. **Immediate** (P0):
   - `/app/podcast/[language]/[location]/page.tsx` 확인
   - `ChapterBasedPodcastGenerator` 컴포넌트 생성 로직 검토
   - `stage` 파라미터 전달 여부 확인

2. **Short-term** (P1):
   - API 엔드포인트에 `stage` 파라미터 지원 추가 또는 복원
   - Stage 1 완료 즉시 페이지 전환 로직 구현
   - Stage 2 비동기 호출 로직 구현

3. **Testing** (P1):
   - 2-stage 플로우 복원 후 E2E 테스트 재실행
   - 사용자 대기 시간 25-30초 달성 검증
   - 백그라운드 생성 중 페이지 사용 가능 여부 확인

**비즈니스 영향**:
- 사용자 대기 시간 90초는 사용자 이탈률 증가 가능성
- 예상 25-30초 대비 3배 증가는 UX 저하
- 경쟁 서비스 대비 불리
